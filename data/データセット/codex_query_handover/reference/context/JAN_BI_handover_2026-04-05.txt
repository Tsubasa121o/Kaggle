4. API SPEC OF NEW JAN BI APP
====================================================================
Base mount path:
- /jan-bi

Endpoints:
1) GET /jan-bi/api/status
   Returns source + loaded_at + coverage summary.

2) POST /jan-bi/api/load
   Body:
   - source: "sample" or "db"
   - start_date: int (e.g. 20130101)
   Behavior:
   - sample: loads CSV bundle from JAN_BI_SAMPLE_DIR
   - db: loads from SQL Server using JAN_BI_DB_CONN_STR

3) GET /jan-bi/api/options
   Returns filter option lists:
   jan, model, color, size, prefecture, customer, industry

4) GET /jan-bi/api/overview?[filters...]
   Returns:
   - KPI totals
   - time-series arrays
   - top_jan
   - top_customer

5) GET /jan-bi/api/correlation?[filters...]
   Returns correlation matrix for metrics.
   Default metrics:
   sales_qty, order_qty, receipt_qty, return_qty

6) GET /jan-bi/api/regression?jan=...&x_metric=...
   Returns:
   - simple regression (x_metric -> sales_qty)
   - multiple regression (fixed feature set)

7) GET /jan-bi/api/data-sufficiency
   Returns per-JAN readiness flags and summary counts.

====================================================================
5. REGRESSION/SUFFICIENCY RULES IN CODE
====================================================================
Current implementation rules:
- Correlation ready:
  observations >= 20 (daily points after aggregation)
- Simple regression ready:
  active sales days >= 30 (rule-of-thumb)
- Multiple regression ready:
  active sales days >= 80 (rule-of-thumb in sufficiency report)
  AND API-level multiple regression check:
    n_obs >= max(60, features*12)
    condition number <= 1e8

Multiple regression features:
- order_qty
- receipt_qty
- return_qty
- sales_lag_1
- sales_lag_7
- is_weekend

6. DATA SOURCE DETAILS
====================================================================
6.1 sample mode
Expected current default folder:
E:\GitHub\Kaggle\data\kimono_fabric\21SJ-14K 分析

Parser logic:
- Detects file roles by column count and numeric/non-numeric header behavior.
- Normalizes JAN to 13-digit strings.
- Builds daily integrated table from:
  sales + orders + receipts + returns
- If sales rows contain negative quantity, negative component is treated as return_qty.

6.2 db mode
Requires environment variable:
- JAN_BI_DB_CONN_STR

Queries used:
- Sales from SYKD/SYKH with customer/prefecture/industry enrichment
- Orders from HACD/HACH
- Receipts from NYKD/NYKH

Default start date:
- JAN_BI_DB_START_DATE, fallback 20130101
