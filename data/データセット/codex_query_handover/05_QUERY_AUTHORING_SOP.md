# Query Authoring SOP

## 1. 受領時ヒアリング（最低限）
- 何を見たいか（売上/発注/入荷/発注残/在庫）
- 粒度（JAN, 日付, 得意先, 地域, 発注No）
- 期間（from/to）
- JAN条件（固定リストか、型番探索か）
- 必要出力列（名称系, 数量系, 補助列）

## 2. 事前確認
1. `03_QUERY_INVENTORY.md` で近いクエリを選ぶ
2. 定義書で列存在を確認
3. JOINキーを `02_TABLE_JOIN_DICTIONARY.md` で確認
4. 日付が int か datetime かを確認（本案件はほぼ int）

## 3. SQL作成基本形
- 文字列コード: `RTRIM`
- 日付表示: `CAST(... AS VARCHAR(8))`
- 集計: `SUM(...) + GROUP BY` で粒度を明示
- リスト条件: `target_jan` CTE or `IN (...)`
- ソート: 利用者が追える順（JAN, 日付 など）

## 4. 保存ルール
- 保存先は必ず `query_output`
- ファイル名に用途を明記（例: `21SJ-14K_JAN別_発注日_発注数量_2024以降.txt`）
- 参照元コピー（`reference\query_source`）は直接上書きしない

## 5. 最終検証（必須）
1. 保存したSQLを再読込して目視確認
2. 粒度が依頼と一致しているか確認
3. 期間条件とJAN件数を確認
4. ORDER BYが出力目的に合うか確認
5. 出力列名の日本語ラベルを最終確認

## 6. Codex返答フォーマット（推奨）
1. 実施内容（1-3行）
2. 作成ファイル絶対パス
3. SQL全文
4. 補足（粒度・注意事項）

## 7. 典型ミスと回避
- ミス: `HACH.hach_jno` と `HACH.hach_id` を混同
  - 回避: ヘッダ結合は `hacd_hid=hach_id`、発注No対応は `hach_jno`
- ミス: JANを数値化して先頭ゼロ消失
  - 回避: 文字列13桁固定
- ミス: `SYKD.sykd_suryo` の負数を売上として集計
  - 回避: 返品扱い条件を明示
- ミス: `RTRIM` を外して一致しない
  - 回避: コード比較は基本 `RTRIM`

## 8. 発注残クエリ固有注意
- 突合キーは `po_no + jan_code`
- 部分入荷と完納を分岐する
- 経過日数は `po_date` 起点で算出

## 9. 変更管理
- SQL追加/更新時は `08_CHANGELOG_TEMPLATE.md` に追記
- JAN件数変更時は `03` と `04` を同時更新
